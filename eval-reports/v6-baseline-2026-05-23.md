## TL;DR — surprising result

**v6 underperforms v3 in our re-measurement on Sonnet 4** (2.95 vs 3.20,
−0.25 pts), even though the PR's own A/B reported v6 as the best
cycle (3.27 vs the PR's pre-merge v3 baseline of 2.88).

| Cycle | Score (Sonnet, this measurement) | Score (PR's A/B, pre-merge) | Δ vs PR |
|---|---:|---:|---:|
| v3 baseline | **3.20** | 2.88 | +0.32 |
| v6 | **2.95** | 3.27 | −0.32 |

**Most likely explanation**: the PR's A/B compared variants against an
engine *without* the final 5 validator guards. Our measurement compares
the same variants against an engine *with* those guards. The validator
guards add ~0.3 pts to v3 baseline (catching things the v6 prompt was
hand-rolled to compensate for). On v6, the validator guards now over-
constrain — v6's prompt-level "fixes" stack with the engine's guards
and the judge penalises new failure modes that v3 didn't have.

**Recommendation**: do NOT flip `TUTOR_PROMPT_VARIANT=v6` in production
yet. Run v7 first, and consider re-running both with the full 8-cell
matrix to reduce sample noise.

| Metric | v3 baseline | v6 | Δ |
|---|---:|---:|---:|
| Overall Sonnet score | 3.20 | 2.95 | −0.25 |
| Tool-use rate | 75-100% | **100% (all 4 cells)** | + |
| Answer leaks | 0 | 0 | = |
| Sessions reaching exit_ticket | 4/4 | 4/4 | = |
| `repeated_question` flags | 9 across 4 Sonnet cells | **12 across 4 cells** | worse |
| Wall time per cell | 89-117s | 85-107s | slightly faster |

The 100% tool-use rate on v6 is a real structural win — the v6 prompt
keeps the LLM in the `pose_question` tool path more reliably than v3.
But this doesn't translate to a higher judge score, because the rubric
penalises *what the questions look like*, not just *whether they came via
the tool*.

## Per-principle comparison (Sonnet 4, 4 cells each)

| Principle | v3 | v6 | Δ | Why |
|---|---:|---:|---:|---|
| active_learning | 3.75 | 3.75 | 0 | Both keep the student doing the work |
| direct_instruction_active_practice | 3.50 | **4.00** | **+0.50** | v6 wins — cleaner teach→practice cadence |
| deliberate_practice | 3.25 | 3.00 | −0.25 | v6 slightly less calibrated to persona |
| mastery_learning | 3.00 | 2.50 | −0.50 | v6 declares mastery prematurely (top recommendation) |
| cognitive_load | 3.25 | **3.50** | **+0.25** | v6 wins — fewer "diagram below" hallucinations |
| layering | 3.50 | 3.25 | −0.25 | Minor regression |
| non_interference | 3.25 | 3.00 | −0.25 | Minor regression |
| interleaving | 1.75 | 2.00 | +0.25 | Both very weak; marginal v6 win |
| testing_effect | 3.75 | 3.00 | −0.75 | v6 leans heavily on MCQ; less retrieval pressure |
| **targeted_remediation** | 3.00 | **1.50** | **−1.50** | **Big v6 regression** — see below |
| **Overall** | **3.20** | **2.95** | **−0.25** | |

### Where v6 wins
- `direct_instruction_active_practice` (+0.50) — cleaner cadence
- `cognitive_load` (+0.25) — addresses "look at diagram below" issue cleanly

### Where v6 loses badly
- **`targeted_remediation` (−1.50)** — the new top failure. The judge consistently noted that on wrong answers, the v6 tutor re-asks the same question type rather than dropping back to a simpler prerequisite skill. Pre-merge this principle scored 3.00; post-merge with v6 it drops to 1.50.
- **`testing_effect` (−0.75)** — v6 leans heavily on MCQ practice; lets students pattern-match without genuine retrieval.
- **`mastery_learning` (−0.50)** — v6 declares "you've mastered this" after one independent correct answer. Inflates confidence, skips needed variation.

## Top judge-recommended fixes for v6

From `ab-test-reports-v6-2026-05-23/FINAL_REPORT.md`:

1. **[high] Forbid premature mastery declarations; gate praise on evidence.** "Do NOT use the word 'mastered' or equivalent until the student has produced at least 3 correct independent solves across at least 2 structurally different problem variants."
2. **[high] Require structural variation across consecutive practice items.** "After 2 successful solves of the same template, the next problem MUST vary in at least one of: algebraic expression for an angle (2x, x+30), two unknowns with a relationship, reflex angle, diagram-based reading, or reverse problem."
3. **[high] Require at least one free-response item before declaring mastery.** "Before issuing any 'mastery' or 'excellent work' summary, you MUST give at least one open-response (no MCQ) item and receive a correct unaided answer."
4. **[high] Forbid same-template repetition; mandate interleaving by problem type.** "Across any 4 consecutive practice items, include at least 2 distinct problem structures."
5. **[high] Calibrate item difficulty to 'struggler' persona with a probing first practice.** "For persona=struggler, the first independent practice item must be free-response and require explicit show-of-work."

Note how **the v6 judge recommendations are different from the v3 baseline**'s. v3's top issues were hallucinated diagrams + silent advance; v6's top issues are premature mastery + template repetition + MCQ-overreliance. v6 fixed some things and made others worse.

## How this changes our reading of the PR

The PR header claimed v6 = 3.27 = "best measured score". That number
was real **at the time of the PR's A/B**, but the underlying engine has
changed since:
- The PR introduced 5 new validator guards (`template-repeat`,
  `truncation`, `numeric-mutation`, `filler-reply`, regen dedup) AFTER
  measuring v6.
- The judge cascade was widened (Gemini → OpenAI → Haiku) AFTER.
- Sonnet 4 became the regen model AFTER.

So the v6 = 3.27 number was for "v6 prompt + intermediate engine state".
Our v6 = 2.95 is for "v6 prompt + final post-merge engine". The change
is real and worth understanding before flipping `TUTOR_PROMPT_VARIANT`
in production.

**The PR's deploy recommendation** ("monitor 24-48h after flipping
v6") would catch the regression in prod — but it's cheaper to catch it
here in CI.

## Caveats

- **4-cell sample, single model.** Sonnet 4 only, no Gemini for cost reasons. v3 baseline used 4 Sonnet cells from the 8-cell run; comparison is 4 vs 4 cells on the same lessons/personas/model, so the comparison itself is apples-to-apples but the absolute numbers have wide CIs.
- **Same caveat on synthetic students** — engine bug surfacing, not learning gains.
- **Judge is non-deterministic in practice** even at temp 0 (LLM provider sampling variance). A second run might shift scores by ±0.1.
- **Engine vs. prompt confound** — we can't isolate "what did the prompt change vs what did the engine guards change?" without an old-engine baseline. The PR's pre-merge numbers serve as that, but they used different lessons/personas/judge.

---

## Decision points

1. **Run v7 before flipping anything in prod?** Yes, recommended. v7 reportedly has the best structural cleanliness (8/8 sessions completing). Worth checking if it sidesteps v6's `targeted_remediation` collapse.
2. **Re-run v6 with 8-cell matrix?** Adds Gemini 3 Flash → measures whether v6's regression is model-specific or cross-model. ~$15 extra.
3. **Stay on baseline (v3) in production?** Currently it's the safer choice. v6's structural win on tool-use doesn't justify the −0.25 pt aggregate regression.
