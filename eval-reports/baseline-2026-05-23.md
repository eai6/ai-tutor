# Baseline Eval — 2026-05-23 (post PR #7 merge)

> **Methodology superseded 2026-05-23**: this review uses the 10-principle
> 0-5 rubric from the A/B harness, which was inherited from PR #7's
> iteration framework. The judge has since been switched to the
> BEA-2025 Shared Task taxonomy (4 dimensions, 3 classes — paper-aligned).
> See [`bea-comparison-2026-05-23.md`](bea-comparison-2026-05-23.md) for
> the 3-cycle v3/v6/v7 comparison under the new rubric. The findings in
> this doc about specific failure modes (hallucinated diagrams, silent
> advance, etc.) remain useful as prompt-tuning signal even though the
> numeric scores are not the paper's metric.


First empirical baseline of the tutor on the merged
`feature/science-learning-tier1-v3` codebase. Uses the existing A/B
harness (`scripts/run_ab_test.py` + `scripts/judge_transcripts.py` +
`scripts/generate_reports.py`) against real prod curriculum loaded
into local SQLite via `python manage.py load_prod_dump`.

> **Status**: baseline only. Compare future deploy-triggered runs
> against these numbers. Phase 2 (wire as a post-deploy GitHub
> workflow) is the next step.

---

## TL;DR

- **8 cells** (2 tutor models × 2 lessons × 2 personas) — all reached the exit ticket cleanly, zero answer leaks.
- **Overall judge mean: 3.09 / 5** (Sonnet 3.20 · Gemini 3 Flash 2.98).
- **Math (L1137) 2.85 / 5 vs Geography (L1425) 3.33 / 5** — math worse, gap of 0.48 pts. **Direction matches the paper's 71.4% / 97.1% subject gap.**
- **The new PR validator guards fire on real failures**: 13 `repeated_question` catches, multiple `numeric_mutation` / `figure_ref_without_signal` flags across the 8 cells. Pre-PR these would have shipped silently.
- **Top failure modes still active**: hallucinated diagrams, silent advance past student answer, answer-in-same-turn-as-question, MCQ conversion of free-response.
- **Weakest pedagogy principles**: `interleaving` (1.75 / 2.50), `targeted_remediation` (3.00 / 2.25), `deliberate_practice` (3.25 / 2.25), `mastery_learning` (3.00 / 2.25).

### Methodology caveats — read before drawing strong conclusions

1. **Tutor model in the harness is NOT the prod-default Opus 4.7.** The harness monkey-patches `ModelConfig.get_for('tutoring')` to swap in Sonnet 4 / Gemini 3 Flash so we can compare *prompt* behavior across models. Real prod traffic on `aitutor-pixel-app` runs Opus 4.7. Treat these numbers as "what the engine does with two A/B-candidate tutor models", not as "what production student sessions look like".
2. **Synthetic students, not real students.** Personas are LLM-driven and follow stylised behaviour patterns. They surface engine bugs reliably but don't measure learning gains.
3. **Sample is small** — 8 cells, 4 per subject. Tight confidence intervals are not the goal; surfacing structured failure modes is.
4. **Pass/fail metric vs 0-5 rubric** — the paper's 84.3% pass rate isn't directly comparable to a 0-5 rubric mean. Directional comparisons (math < geography) hold; quantitative deltas do not.

## Wins — what PR #7 measurably improved

These observations are *enabled* by the PR's instrumentation; absent the
new validator guards, several of these signals wouldn't even surface.

1. **13 `repeated_question` catches across 8 sessions.** The new
   `ISSUE_SAME_TEMPLATE_REPEAT` validator (`apps/tutoring/validator.py`,
   added in commit `43fe4b7`) is correctly flagging cases where the tutor
   recycles the same question template with different numerics. Pre-PR
   the engine had no detector for this — the failures would have
   reached students unnoticed.

2. **Zero answer leaks across all 8 cells.** Matches the paper's stated
   invariant. The unified judge + new validator stack hold.

3. **8 / 8 sessions reached `exit_ticket` cleanly.** No infinite hold
   loops, no deadlocks. The `MAX_EXIT_TICKET_HOLD_CYCLES = 5` escape
   valve plus the PR's new `ISSUE_FILLER_REPLY_TEACH` guard (which
   handles "ok"/"yes" student replies without restarting the lesson) are
   doing their job. This is a meaningful regression suite — the paper
   noted stuck-state incidents during data collection.

4. **Tool-use rates 75–100%.** The `pose_question` tool is being used
   reliably; the `ISSUE_NO_QUESTION_TOOL` validator (existing, but
   reinforced by the PR's variants) keeps the LLM in the tool path
   instead of inline-authoring.

5. **Judge cascade in place.** Migrations 0029/0030/0031 wired
   Gemini → OpenAI → Haiku. No judge outages in this run, but the
   cascade exists if Gemini 503s recur.

## Open gaps — where the most room remains

Ranked by judge-surfaced severity × frequency:

### 1. Hallucinated diagrams (cognitive_load) — high severity

The tutor writes "Look at the diagram below..." or "as shown above..."
without any figure tool being invoked. Students search for missing
visuals and respond `"what's the question?"` or `"i don't see"`.

> Example (TUTOR turn 3229): *"Look at the diagram below showing four
> angles around a point. Three angles are given: 70°, 85°, and 100°."*
> — no figure rendered.

Top recommendation from the judge: forbid the phrase pattern. The
`ISSUE_FIGURE_REF_WITHOUT_SIGNAL` validator already catches this; the
fix is in the system prompt, not the validator.

### 2. Silent advance past student answer (mastery_learning, deliberate_practice) — high severity

Tutor moves to the next problem without confirming/correcting the
prior answer. This is **the same failure class the paper identified as
the dominant math problem** (`false_reject` + `over_eager_working_request`,
60% of math failures). Still present after the PR.

> Example: *Student says `x = 170` (which is correct: 80+110+170=360);
> tutor immediately posts the next problem with new numbers, never
> acknowledging the answer.*

The PR's repair templates address this in spirit (issue-type-specific
regen), but the underlying engine still allows it. **This is the single
highest-leverage fix.**

### 3. Answer revealed in the same turn as the question (testing_effect)

Tutor poses a question then includes a definition / worked solution
**after** the prompt, so the student can read the answer before
attempting. Violates retrieval practice.

> Example (TUTOR id=3263): *"Is this true or false? A large-scale map
> (such as 1:25,000) shows a smaller geographic area in greater detail
> than a small-scale map (such as 1:5,000,000)."* — the question
> contains the answer.

### 4. MCQ conversion of free-response (testing_effect)

When the student types a free-response problem (e.g., `"find x. 70°, 85°,
100°, and x°..."`), the tutor reverts to MCQ instead of grading the
numeric answer directly. Weakens retrieval strength.

### 5. Persistent subject gap (math worse than geography)

| Subject | Mean | Notes |
|---|---:|---|
| Geography | 3.33 | Conceptual recall, factual claims, classification |
| Math | 2.85 | Numeric verification, equivalent forms, reasoning chains |

The PR did not close this gap. Per the redesign plan (`memory/tutor_engine_redesign_plan.md`),
Phase 3 (tool-using grader with sympy + pint) is the structural fix —
hands the grader real math tools instead of relying on LLM arithmetic.

### Per-principle weak spots (ranked worst → best)

| Rank | Principle | Sonnet | Gemini | Diagnosis |
|---|---|---:|---:|---|
| 1 | interleaving | 1.75 | 2.50 | Same problem type repeated across turns; no mixing of sub-skills |
| 2 | targeted_remediation | 3.00 | 2.25 | Failed attempts don't trigger prereq practice — tutor reprises the same scaffold |
| 3 | deliberate_practice | 3.25 | 2.25 | Difficulty not calibrated; corrective feedback generic |

## Top judge-recommended system-prompt edits

Ranked by severity × frequency, from `ab-test-reports-baseline-2026-05-23/FINAL_REPORT.md`:

1. **[high] Forbid referencing a diagram unless one is actually rendered.** Add a rule banning `"the diagram"`, `"shown above/below"`, `"look at the figure"` unless a figure tool was invoked the same turn.
2. **[high] Promote free-response when the student initiates it.** Don't convert a student's free-form problem into MCQ.
3. **[high] Mandate explicit answer-checking before next problem.** "Never present a new question without first closing the loop on the previous one."
4. **[high] Require every teach block to end with a concrete student action.** No "dead-end" teach turns ending in `"I'll show you next..."`.
5. **[high] Forbid revealing the answer in the same turn as the question.** Explanatory content must precede the prompt; turn must end at the question.

All five can be added as system-prompt rules with no engine code changes
required. Recommend layering them into the `v8` prompt variant (next
A/B cycle) and re-running this baseline.

## Suspect signals worth investigating

1. **Uniform `turns=7` across all 8 cells.** Either the synthetic
   student is converging too fast (rubber-stamping answers) or the
   `turns` metric is measuring something narrower than student-tutor
   exchanges. Spot-check of `sonnet-4_L1137_capable.md` shows ~10
   actual exchanges in the transcript — confirms the metric is
   undercounting. Worth a one-line fix.

2. **Sonnet `interleaving` = 1.75** — by far the weakest single
   principle / model combo. The judge consistently noted "same problem
   type repeated 3-4 turns in a row". Hypothesis: the lesson-step
   content is monotonic per step and the engine doesn't shuffle across
   step concepts. May be a curriculum-shape issue more than a tutor-
   prompt issue.

3. **Gemini 3 Flash is 2.2× slower than Sonnet 4** (224s vs 100s mean
   cell wall time). Despite both being "fast" tier models. Gemini's
   tool-call round-tripping is the likely culprit. Not a quality
   problem, but a cost / latency one if Gemini ever becomes the prod
   tutor model.
