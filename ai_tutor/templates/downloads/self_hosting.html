{% trans "Run AI Tutor yourself" %}

{% trans "On your own server, with student data inside your own borders." %}

{% trans "Where data goes." %} {% blocktrans trimmed %} Course material, uploaded figures and student records stay in your database and on your disk. Embeddings are computed locally — the all-MiniLM-L6-v2 model runs inside the app container, so your curriculum is never sent anywhere to be indexed. But the text of each student message is sent to Anthropic, OpenAI or Google to be answered, leaving your network. If that is not acceptable, run a local model instead — see below. {% endblocktrans %}

{% trans "First start needs internet" %} {% blocktrans trimmed %} even with a local model: the app downloads the embedding model (~90 MB) from HuggingFace on first boot. For an air-gapped install, warm the cache on a connected machine first and copy the volume across. {% endblocktrans %}

{% trans "Pick your deployment shape before you start" %}

{% blocktrans trimmed %} Almost every install problem below comes from picking the wrong one, because the default configuration assumes the first. {% endblocktrans %}

{% trans "Public server" %} {% trans "LAN-only" %} {% trans "Laptop" %}
{% trans "Reachable from" %} {% trans "internet" %} {% trans "school network" %} {% trans "one machine" %}
{% trans "Needs a domain" %} {% trans "yes" %} {% trans "no" %} {% trans "no" %}
{% trans "HTTPS" %} {% trans "automatic" %} {% trans "none" %} {% trans "none" %}
SITE_DOMAIN {% trans "your real domain" %} localhost localhost
{% trans "Caddy site block" %} {$SITE_DOMAIN} :80 :80
HTTPS_EDGE true false false
{% trans "Port binding" %} 80:80 80:80 127.0.0.1:80:80
{% blocktrans trimmed %} The LAN-only and laptop shapes send session and CSRF cookies in the clear. Only use them where the traffic never leaves a building you control, or on a single machine. Never on café or conference wifi with real student data. {% endblocktrans %}

{% trans "With Docker" %}{% trans "recommended" %}

{% blocktrans trimmed %} A Linux server with 4 vCPU, 8 GB RAM and 60 GB disk; Docker with the Compose plugin; a domain pointing at it, for the public-server shape only. Brings its own database and certificates. {% endblocktrans %}

1{% trans "Get the deployment files" %}

mkdir -p ai-tutor && cd ai-tutor

# the deployment files ship inside the image, so they always match it
docker run --rm ghcr.io/eai6/ai-tutor:latest \
  tar -C /app/deploy/compose -c \
      docker-compose.yml Caddyfile env.example backup.sh restore.sh > deploy.tar

tar -tvf deploy.tar   # inspect: no leading / and no .. in any path
tar -xf deploy.tar
{% trans "Where the files land, and what to read before running them" %}

{% blocktrans trimmed %} Files land flat in ai-tutor/, not in a deploy/compose/ subdirectory. This is also where backup.sh lives, so that is the directory you run it from later. {% endblocktrans %}

{% blocktrans trimmed %} That first docker run already pulls the full image (~7 GB), so the docker compose pull in step 4 is usually instant. {% endblocktrans %}

{% blocktrans trimmed %} Read docker-compose.yml and Caddyfile before running them. Both are commented and short. Caddyfile in particular contains a ready-made plain-HTTP block you will need if you are not on the public-server shape. {% endblocktrans %}

{% blocktrans trimmed %} Optionally pin the exact image, so a later pull cannot drift from the compose file you just extracted: {% endblocktrans %}

{% verbatim %} 
docker inspect --format='{{index .RepoDigests 0}}' ghcr.io/eai6/ai-tutor:latest
# put the resulting name@sha256:... into the app service's image: line
{% endverbatim %}

2{% trans "Configure .env" %}

cp env.example .env && chmod 600 .env
{% blocktrans trimmed %} env.example ships placeholder values, not blanks — SITE_DOMAIN=tutor.education.gov.xx and ACME_EMAIL=ict@education.gov.xx. These look filled in and are not. Replace both, or Caddy will spend thirty days failing to get a certificate for a domain that does not exist. {% endblocktrans %}
{% trans "Every required variable, and what to put in it" %}
{% trans "Variable" %}{% trans "Notes" %}
SECRET_KEY python3 -c 'import secrets; print(secrets.token_urlsafe(64))'
POSTGRES_PASSWORD {% blocktrans trimmed %}avoid @ : / ? — they break DATABASE_URL parsing{% endblocktrans %}
SITE_DOMAIN {% blocktrans trimmed %}compose enforces this with :?. Use localhost if you have no domain{% endblocktrans %}
ALLOWED_HOSTS {% trans "the hostname students will type, comma-separated if more than one" %}
CSRF_TRUSTED_ORIGINS {% trans "must include the scheme" %}
{% trans "one provider API key" %} {% blocktrans trimmed %}or use the local-llm profile{% endblocktrans %}

{% blocktrans trimmed %} Optional: ACME_EMAIL (only used when requesting a certificate) and HTTPS_EDGE. {% endblocktrans %}

{% trans "Public server:" %}

SITE_DOMAIN=tutor.yourdomain.example
ACME_EMAIL=you@yourdomain.example
ALLOWED_HOSTS=tutor.yourdomain.example
CSRF_TRUSTED_ORIGINS=https://tutor.yourdomain.example
HTTPS_EDGE=true

{% trans "LAN-only or laptop:" %}

SITE_DOMAIN=localhost
#ACME_EMAIL=
ALLOWED_HOSTS=localhost,127.0.0.1
CSRF_TRUSTED_ORIGINS=http://localhost
HTTPS_EDGE=false

{% blocktrans trimmed %} Duplicate keys are easy to introduce while editing, and the last one silently wins. Check: {% endblocktrans %} 

grep -n 'HTTPS_EDGE\|ALLOWED_HOSTS\|CSRF_TRUSTED\|SITE_DOMAIN' .env

3{% trans "Configure Caddy — only if you are not on a public domain" %}

{% blocktrans trimmed %} On the public-server shape there is nothing to do here. Skip to step 4. {% endblocktrans %}

{% trans "Switching Caddy to plain HTTP (LAN-only or laptop)" %}

{% blocktrans trimmed %} Keep a copy of the original first: cp Caddyfile Caddyfile.orig. Then delete the global email block and replace the whole {$SITE_DOMAIN} block with the plain-HTTP block already commented at the bottom of the file: {% endblocktrans %} 

:80 {
    encode gzip

    reverse_proxy app:8000 {
        header_up X-Real-IP {remote_host}
        transport http {
            read_timeout 300s
            write_timeout 300s
        }
    }

    log {
        output stdout
        format console
    }
}
{% blocktrans trimmed %} Both changes are needed — this one and HTTPS_EDGE=false. Doing only one gives you a silent 403; see troubleshooting. {% endblocktrans %}

{% blocktrans trimmed %} Laptop only: in docker-compose.yml, bind Caddy to loopback and drop 443, which nothing listens on now. {% endblocktrans %} 

    ports:
      - "127.0.0.1:80:80"

{% blocktrans trimmed %} "80:80" binds every interface including wifi. Docker writes its own iptables rules ahead of ufw, so a firewall rule will not substitute for this — the bind address is the only control that works. {% endblocktrans %}

4{% trans "Start it" %}

docker compose pull        # ~7 GB, once
docker compose up -d
docker compose logs -f app
{% blocktrans trimmed %} Wait before doing anything else. up -d returns when containers have started, not when the app is usable. First boot runs 200+ database migrations, downloads the embedding model and indexes the seeded curriculum — a couple of minutes on modest hardware. {% endblocktrans %}
{% trans "What “ready” looks like in the log" %}

{% trans "A line like this one:" %}

Indexed. Collection size: 0 → 151.

{% trans "Or check the health state, which is the same signal:" %}

docker compose ps    # wait for app to show (healthy)

{% blocktrans trimmed %} A BertModel LOAD REPORT line flagging embeddings.position_ids as UNEXPECTED during this is normal and can be ignored. {% endblocktrans %}

5{% trans "Create the admin account" %}

{% trans "Only after the app reports healthy." %}

docker compose exec app python manage.py createsuperuser
{% trans "Type a username — do not accept the default" %}

{% blocktrans trimmed %} Leaving it blank accepts the container's OS user, which gives you an account called root — easy to do by accident and confusing later. To fix it afterwards: {% endblocktrans %} 

docker compose exec app python manage.py changepassword <name>

{% blocktrans trimmed %} No API key? docker compose --profile local-llm up -d runs a small model on the server instead. Weaker at tutoring than a cloud model, and slower without a GPU — but it needs no account anywhere and nothing leaves your network. If you already run an OpenAI-compatible endpoint of your own, point a model config at it instead. {% endblocktrans %}

{% trans "With pip, no Docker" %}

{% blocktrans trimmed %} For a server where containers are not allowed. Needs Python 3.12 or newer and PostgreSQL with the pgvector extension. You supply the database, the reverse proxy and the file ownership yourself: this path automates much less than the Docker one, and every step below that looks fussy is there because skipping it produces a failure that does not name its own cause. {% endblocktrans %}

{% if server_wheel %}

{% trans "Decide the service account first." %} {% blocktrans trimmed %} The generated systemd unit runs as an unprivileged user and reads files that the install steps create as root. Nothing reconciles those two automatically, so pick the account now — these commands use aitutor; substitute your own throughout. {% endblocktrans %}

{% blocktrans trimmed %} Be logged in as that account when you run ai-tutor systemd in step 7: it writes $SUDO_USER, falling back to $USER, into the unit's User= line. The PostgreSQL role created in step 3 happens to share the name; they are separate accounts and need not match. {% endblocktrans %}

1{% trans "Create the virtualenv" %}

sudo apt install python3-venv python3-dev libpq-dev build-essential
sudo python3 -m venv /opt/ai-tutor/venv
/opt/ai-tutor/venv/bin/python -V     # confirm 3.12 or newer
{% trans "Use python3, not python3.12 — and do not skip python3-venv" %}

{% blocktrans trimmed %} The version is a floor, not a pin. Distributions that have moved past 3.12 have no python3.12 binary at all, so naming it gives you sudo: python3.12: command not found followed by two misleading cascade errors about pip and ai-tutor not existing. {% endblocktrans %}

{% blocktrans trimmed %} Without python3-venv, -m venv can create the directory but leave no pip inside — which produces an error identical to the one above, for an entirely different reason. {% endblocktrans %}

2{% trans "Install the wheel" %}

sudo /opt/ai-tutor/venv/bin/pip install --upgrade pip
sudo /opt/ai-tutor/venv/bin/pip install {{ server_wheel_url }}

{% blocktrans trimmed %} Several GB and several minutes — torch arrives as a transitive dependency of the embedding stack. {% endblocktrans %}

{% trans "If it stalls on “Building wheel for …”" %}

{% blocktrans trimmed %} The py3-none-any tag applies to ai_tutor itself, not to its dependencies. If one of those has no wheel for your Python version, pip falls back to a source build. The libpq-dev and build-essential packages installed in step 1 cover the usual culprit. {% endblocktrans %}

3{% trans "Prepare the database" %}

sudo -u postgres createuser --pwprompt aitutor
sudo -u postgres createdb -O aitutor aitutor
sudo -u postgres psql -d aitutor -c 'CREATE EXTENSION IF NOT EXISTS vector;'
{% blocktrans trimmed %} Create the extension before migrating. Migrations do run CREATE EXTENSION IF NOT EXISTS vector themselves, but that statement needs a privileged role — and the account in your DATABASE_URL should not be one. Skip this and the migration fails on the first vector column. {% endblocktrans %}

4{% trans "Initialise and configure" %}

sudo /opt/ai-tutor/venv/bin/ai-tutor init

{% blocktrans trimmed %} Writes /etc/ai-tutor/ai-tutor.env with a generated SECRET_KEY. Edit it and set at minimum: {% endblocktrans %} 

DATABASE_URL=postgresql://aitutor:PASSWORD@localhost:5432/aitutor
ALLOWED_HOSTS=127.0.0.1,localhost
CSRF_TRUSTED_ORIGINS=http://127.0.0.1:8000
HTTPS_EDGE=false

{% blocktrans trimmed %} Add a provider API key too. Set HTTPS_EDGE=true, and the real scheme in CSRF_TRUSTED_ORIGINS, once a TLS-terminating proxy is in front. {% endblocktrans %}

{% trans "DATABASE_URL is not optional, and nothing enforces it." %} {% blocktrans trimmed %} Leave it unset and Django silently falls back to SQLite at /var/lib/ai-tutor/db.sqlite3. migrate succeeds, seed succeeds, the app starts and serves — on a database with no pgvector. You get a working-looking install that is not the system you are evaluating. {% endblocktrans %}

{% trans "Check for the tell:" %}

grep -n DATABASE_URL /etc/ai-tutor/ai-tutor.env
ls -la /var/lib/ai-tutor/          # a db.sqlite3 here means it fell back

{% blocktrans trimmed %} If you find one, set DATABASE_URL, move the file aside, and re-run migrate and seed. {% endblocktrans %}

5{% trans "Fix ownership — before anything else runs" %}

{% blocktrans trimmed %} The install steps ran as root. The service will not. Reconcile them now, or it crash-loops on startup with PermissionError: [Errno 13] Permission denied: '/etc/ai-tutor/ai-tutor.env' and never reaches Django. {% endblocktrans %} 

sudo mkdir -p /var/lib/ai-tutor
sudo chown -R aitutor:aitutor /var/lib/ai-tutor
sudo chown root:aitutor /etc/ai-tutor/ai-tutor.env
sudo chmod 640 /etc/ai-tutor/ai-tutor.env
sudo chmod 755 /etc/ai-tutor

sudo -u aitutor head -1 /etc/ai-tutor/ai-tutor.env    # prove it worked

{% blocktrans trimmed %} Group-readable rather than world-readable: that file holds the SECRET_KEY, the database password and your provider key. {% endblocktrans %}

6{% trans "Migrate, seed, collect static, create the admin" %}

{% blocktrans trimmed %} Run these as the service user, not as root. Running them under plain sudo recreates the ownership problem you just fixed, on every file they touch. {% endblocktrans %} 

run() { sudo -u aitutor env \
  AI_TUTOR_ENV_FILE=/etc/ai-tutor/ai-tutor.env \
  AI_TUTOR_DATA_DIR=/var/lib/ai-tutor \
  /opt/ai-tutor/venv/bin/ai-tutor "$@"; }

run migrate
run seed
run collectstatic --noinput
run createsuperuser

{% trans "collectstatic is required." %} {% blocktrans trimmed %} Its omission is fatal rather than cosmetic: the app uses Django's manifest static-files storage, which resolves every asset through a staticfiles.json that only collectstatic generates. Without it every page — including the login form — returns HTTP 500 with ValueError: Missing staticfiles manifest entry for 'admin/css/base.css'. The Docker image does this at build time, so it only bites the pip path. {% endblocktrans %}

{% trans "Confirm:" %} ls /var/lib/ai-tutor/staticfiles/staticfiles.json

{% trans "Type a username at createsuperuser" %}

{% blocktrans trimmed %} Leaving it blank accepts the OS user and silently gives you an account called root — the same trap as the Docker path. {% endblocktrans %}

7{% trans "Install the service" %}

sudo /opt/ai-tutor/venv/bin/ai-tutor systemd | sudo tee /etc/systemd/system/ai-tutor.service
sudo systemctl daemon-reload && sudo systemctl enable --now ai-tutor
systemctl status ai-tutor --no-pager

{% trans "Read the generated unit before enabling it." %} {% blocktrans trimmed %} ProtectHome=yes makes /home invisible to the service, and both the HuggingFace cache and gunicorn's control server default to paths under it — Permission denied: '/home/<user>'. Redirect them with sudo systemctl edit ai-tutor: {% endblocktrans %} 

[Service]
Environment=HF_HOME=/var/lib/ai-tutor/hf
Environment=HOME=/var/lib/ai-tutor
{% trans "Reading the service state" %}

{% blocktrans trimmed %} Active: activating (auto-restart) means it is crash-looping. Read the traceback with journalctl -u ai-tutor -n 50 --no-pager, fix it, then run sudo systemctl reset-failed ai-tutor before restarting — otherwise the accumulated restart counter gets in the way. {% endblocktrans %}

{% blocktrans trimmed %} Active: active (running) with Listening at: http://...:8000 is success. {% endblocktrans %}

8{% trans "Bind, proxy and verify" %}

{% blocktrans trimmed %} Gunicorn binds 0.0.0.0:8000 by default — reachable from your whole network, in the clear, with no proxy in front. Unlike the Docker path, a firewall is effective here; narrowing the bind is better still. {% endblocktrans %} 

sudo ufw deny 8000
# or, in /etc/ai-tutor/ai-tutor.env:  AI_TUTOR_BIND=127.0.0.1:8000

curl -sI http://127.0.0.1:8000/admin/     # want 302 to /admin/login/
{% blocktrans trimmed %} Your reverse proxy must allow a 300-second read and write timeout. A tutoring turn takes 20–90 seconds; a default 60-second timeout cuts the connection, the student sees a blank reply, and your log records a completed request. {% endblocktrans %}

{% blocktrans trimmed %} Then open it in a browser. A 302 from curl only proves routing works — it never renders a template, so it will not catch a missing collectstatic. The browser will. {% endblocktrans %}

{% trans "Troubleshooting" %}

{% trans "Login form reloads, no error message" %}

{% blocktrans trimmed %} The commonest failure, and a silent one. Django marks session and CSRF cookies Secure; a browser will not send those over plain HTTP, so the login simply bounces. {% endblocktrans %}

{% blocktrans trimmed %} Finish the HTTPS setup, or set HTTPS_EDGE=false and switch the Caddyfile to the :80 block. Both are required. Then run docker compose up -d — not restart, see below. {% endblocktrans %}

{% trans "If it persists, check what Django actually resolved:" %}

docker compose exec app python -c "
import django; django.setup()
from django.conf import settings
print(settings.ALLOWED_HOSTS, settings.CSRF_TRUSTED_ORIGINS)
"
.env {% trans "edits appear to do nothing" %}

{% blocktrans trimmed %} docker compose restart does not re-read .env. Neither do port or volume changes take effect. Always use docker compose up -d, which recreates the affected containers. {% endblocktrans %}

relation "auth_user" does not exist

{% blocktrans trimmed %} You ran createsuperuser before migrations finished — most likely by pasting it together with up -d. Nothing is broken. Wait for the app to report healthy and run it again. {% endblocktrans %}

ERR_SSL_PROTOCOL_ERROR {% trans "/ “sent an invalid response”" %}

{% blocktrans trimmed %} Caddy is redirecting to HTTPS but has no certificate to serve for the hostname you asked for. Either the certificate was never issued (see the next entry), or you are browsing to localhost while the only site block is for {$SITE_DOMAIN} — no site matches, so the handshake is aborted before any HTTP happens. Switch to the :80 block. {% endblocktrans %}

invalidContact — {% trans "domain does not end with a valid public suffix" %}

{% blocktrans trimmed %} ACME_EMAIL is still the placeholder from env.example. .xx is not a real TLD, so Let's Encrypt refuses the account and Caddy falls back to ZeroSSL, which refuses too. Caddy then retries with backoff for 30 days. {% endblocktrans %}

{% blocktrans trimmed %} Set a real address, or remove the ACME block entirely if you are not using a public domain. The same applies to SITE_DOMAIN: issuance also needs the domain to already resolve to this server, with ports 80 and 443 reachable from the internet. A laptop behind NAT cannot satisfy that. {% endblocktrans %}

{% trans "To clear the failed account state afterwards:" %}

docker compose down && docker volume rm ai-tutor_caddy_data
{% trans "Browser still redirects to HTTPS after fixing the Caddyfile" %}

{% blocktrans trimmed %} The old redirect was a 308 Permanent, and browsers cache those aggressively — you will be sent to https:// without Caddy ever being asked. Use a private window, or clear site data for that host. {% endblocktrans %}

{% trans "Confirm from the shell, which does not cache:" %}

curl -sI http://localhost/admin/    # want 302 to /admin/login/, not 308
{% trans "Docker on Kali: apt has no repository for it" %}

{% blocktrans trimmed %} Docker's apt repository has no kali-rolling suite. Use Kali's own package, then install the Compose plugin binary directly rather than falling back to the v1 docker-compose script: {% endblocktrans %} 

sudo apt install docker.io
mkdir -p ~/.docker/cli-plugins
curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 \
  -o ~/.docker/cli-plugins/docker-compose
chmod +x ~/.docker/cli-plugins/docker-compose

{% blocktrans trimmed %} Adding yourself to the docker group is effectively passwordless root — anyone who can reach the Docker socket can mount / into a container. On a workstation, consider sudo docker instead. {% endblocktrans %}

{% trans "pip path: the service crash-loops with PermissionError on ai-tutor.env" %}

{% blocktrans trimmed %} ai-tutor init runs as root and writes the file 0600 root:root. ai-tutor systemd generates a unit that runs as an unprivileged user. Nothing reconciles them. {% endblocktrans %}

{% blocktrans trimmed %} See pip step 5 — chown root:<user> and chmod 640 the env file, chown -R the data directory, then systemctl reset-failed before restarting. {% endblocktrans %}

{% trans "pip path: every page returns 500, “Missing staticfiles manifest entry”" %}

{% blocktrans trimmed %} collectstatic was never run. Django's manifest storage raises rather than degrading to unstyled output, so even the login form fails. See pip step 6. {% endblocktrans %}

{% blocktrans trimmed %} Note that curl -I /admin/ still returns a healthy 302, because a redirect renders no template — this failure is only visible in a browser. {% endblocktrans %}

{% trans "pip path: it started, but is it using the right database?" %}

{% blocktrans trimmed %} If DATABASE_URL is unset, Django falls back to SQLite and everything appears to work — with no pgvector behind retrieval. Run ls -la /var/lib/ai-tutor/: a db.sqlite3 there means the fallback happened. {% endblocktrans %}

{% trans "Keep it running" %}

{% blocktrans trimmed %} Back up both halves together. The database holds the reference to every uploaded figure and the disk holds the file, so a database restored against older media leaves lessons with broken images and reports no error. {% endblocktrans %} 

# Docker — from the directory you extracted into
cd ai-tutor && ./backup.sh

# pip
pg_dump -Fc aitutor > /mnt/backup/aitutor-$(date +%F).dump
tar czf /mnt/backup/media-$(date +%F).tar.gz -C /var/lib/ai-tutor media

{% blocktrans trimmed %} A backup that only exists on the machine it backs up is not a backup, and these contain student records — store them encrypted, off the machine. {% endblocktrans %}

{% blocktrans trimmed %} Test a restore before you need it, while the only data is seed data and your own test conversations. That is the one moment when getting it wrong costs nothing. {% endblocktrans %}

{% blocktrans trimmed %} Worth also confirming state survives a stop, which tells you the named volumes are doing their job — sign in again afterwards, and the curriculum should still be indexed: {% endblocktrans %} 

docker compose down && docker compose up -d

{% trans "Upgrading" %}

# Docker — migrations run on start
docker compose pull && docker compose up -d

# pip — nothing is automatic here
sudo /opt/ai-tutor/venv/bin/pip install --upgrade ai-tutor
sudo /opt/ai-tutor/venv/bin/ai-tutor migrate
sudo systemctl restart ai-tutor

{% blocktrans trimmed %} Take a backup first — migrations are not reversible. And if you edited Caddyfile or docker-compose.yml, keep those edits under version control or in .orig copies: a future release may ship changed versions, and you will want to see what changed rather than re-deriving your local modifications from memory. {% endblocktrans %}
