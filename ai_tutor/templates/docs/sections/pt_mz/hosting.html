Três caminhos suportados para uma instalação em servidor, mais dois formatos offline. Todos executam a mesma aplicação; diferem em quem opera a máquina por baixo e em quanta canalização envolvente vem já montada. O que se segue é o detalhe operacional — o manual de alojamento próprio acompanha a aplicação e prevalece se algum dia os dois divergirem.

  • Escolha A se tem um servidor ou uma exigência de centro de dados, ou se quer todo o sistema dentro de uma máquina que possa apontar. É o mais simples de compreender e o mais barato de operar.
  • Escolha B se já opera na AWS, precisa que sobreviva a uma falha de máquina sem intervenção de ninguém, ou espera crescer para além de um servidor.

Nenhum deles altera o que o tutor faz, nem onde corre o modelo. Isso é a secção 5.

Caminho A — um servidor

Três contentores, dois volumes, um servidor. A base de conhecimento é guardada como vectores dentro do Postgres, pelo que não há nenhuma base de dados vectorial separada para operar.

        Internet
            │
          Caddy            o TLS termina aqui; o certificado é
            │              obtido e renovado automaticamente
            ▼
     Django + Gunicorn  ── volume de media (figuras carregadas)
            │
            ▼
   PostgreSQL + pgvector ── volume de dados

O que é preciso

  • Um servidor Linux: 4 vCPU, 8 GB de RAM, 60 GB de disco. Funciona em x86-64 e em ARM. Um VPS de 2 GB não aguenta isto — a imagem tem cerca de 7 GB, com uma versão do PyTorch para CPU, um modelo de reconhecimento de fala e uma voz.
  • Se construir em vez de descarregar, conte com 25 GB livres: a cache de camadas é confortavelmente maior do que o resultado.
  • Docker e o plugin Compose.
  • Um nome de domínio a apontar para o IP público do servidor, com as portas 80 e 443 acessíveis. Sem isso não é possível emitir HTTPS.
  • Pelo menos uma chave de API de um fornecedor de modelos — ou nenhuma, se usar o modelo local incluído descrito abaixo.

Instalar

São precisos cinco ficheiros: a definição do compose, a configuração de TLS, um modelo de configuração e os scripts de cópia de segurança e de restauro. Retire-os da imagem publicada — sem código-fonte, sem acesso ao repositório, e não podem ficar desfasados da imagem que configuram.

mkdir -p ai-tutor && cd ai-tutor

docker run --rm ghcr.io/eai6/ai-tutor:latest \
  tar -C /app/deploy/compose -c \
      docker-compose.yml Caddyfile env.example backup.sh restore.sh | tar -x

cp env.example .env
chmod 600 .env

Abra o .env e preencha tudo o que estiver marcado como REQUIRED; cada entrada diz o que é e o que falha sem ela. Gere os dois segredos em vez de os inventar:

python3 -c "import secrets; print(secrets.token_urlsafe(64))"   # SECRET_KEY
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # POSTGRES_PASSWORD

Depois descarregue a imagem e inicie:

docker compose pull        # ~7 GB, uma vez
docker compose up -d
docker compose logs -f app

FAÇA PULL ANTES DE UP

Se a imagem ainda não estiver na máquina, o docker compose up constrói-a a partir do código — o que exige o código-fonte, cerca de 25 GB de disco livre e bastante tempo. A imagem publicada é x86-64; num servidor ARM, clone o repositório e execute docker compose build, que é também como se produz uma imagem ARM. Nada está preso a uma arquitectura.

Começar sem qualquer conta de fornecedor

docker compose --profile local-llm up -d

Isso acrescenta um contentor com um modelo local, descarrega um modelo de cerca de 2,6 GB no primeiro arranque e aponta o tutor para ele automaticamente. Encare-o como uma forma de começar sem uma conta comercial, e não como um equivalente: um modelo local pequeno é mensuravelmente mais fraco a ensinar, precisa de cerca de 4 GB de RAM além da aplicação e é mais lento num servidor sem GPU. Acrescente mais tarde uma chave de fornecedor e reinicie — a configuração local afasta-se sozinha.

Primeira execução

  1. Crie a conta de administrador: docker compose exec app python manage.py createsuperuser
  2. Inicie sessão em https://<o-seu-dominio>/admin/ e defina que modelo serve que finalidade em LLM → Model configs. Nada funciona enquanto, no mínimo, a tutoria não apontar para um fornecedor cuja chave tenha fornecido.
  3. Crie a instituição e carregue um currículo pelo painel do professor.
  4. Faça um turno de tutoria. É este o verdadeiro teste — exercita a base de dados, a base de conhecimento, as credenciais e a media numa só acção. Uma verificação de saúde não o faz.

Actualizar

cd ai-tutor
docker compose pull
docker compose up -d

As migrações correm automaticamente no arranque. Faça primeiro uma cópia de segurança. Para fixar uma versão em vez de seguir a mais recente, defina IMAGE_TAG=v1.2.0 no .env — fixar torna a actualização algo que decide, e a reversão uma questão de mudar uma linha.

Caminho B — a sua própria conta AWS

DNS e uma firewall à frente, um balanceador de carga a terminar o TLS, a aplicação em Fargate em sub-redes privadas sem endereço público, um Postgres gerido ao lado, e Internet apenas de saída através de um gateway NAT. O custo desta configuração está na secção 6.

O que é preciso antes

  • Uma conta AWS e um papel que possa criar recursos de VPC, ECS, RDS, S3, IAM, WAF e Route 53.
  • Um domínio que controle — não é possível emitir um certificado para o nome de anfitrião de um balanceador de carga pertencente à AWS.
  • Pelo menos uma chave de API de um fornecedor de modelos.
  • Instalados localmente: git, aws CLI v2, pulumi, docker, Python 3.12.
  • O repositório, para o programa de infra-estrutura como código em infra/aws/. O caminho A pode correr apenas a partir da imagem publicada; este não.

Passo 1 — Clonar e configurar a stack

git clone <repo> ai-tutor && cd ai-tutor/infra/aws
python -m venv venv && ./venv/bin/pip install -r requirements.txt

aws configure                 # ou aws sso login
pulumi login --local          # estado em ~/.pulumi; faça cópia disto
pulumi stack init prod

pulumi config set aws:region eu-west-1
pulumi config set aitutor-aws:db-instance-class db.t4g.medium
pulumi config set aitutor-aws:db-storage-gb 50
pulumi config set aitutor-aws:min-tasks 1
pulumi config set aitutor-aws:max-tasks 4

# Defina a palavra-passe da base de dados — NÃO deixe que seja gerada
pulumi config set --secret aitutor-aws:db-password "<uma palavra-passe longa e aleatória>"
pulumi config set --secret aitutor-aws:django-secret-key "<50+ caracteres aleatórios>"
pulumi config set --secret aitutor-aws:anthropic-api-key "sk-ant-..."

Passo 2 — Levantar a infra-estrutura

pulumi up                                        # reveja o plano e confirme
pulumi config set aitutor-aws:enable-ecs true    # depois acrescente o serviço
pulumi up

O serviço está deliberadamente por trás dessa segunda opção, para que a base possa ser verificada antes de correr seja o que for sobre ela.

Passo 3 — Domínio e HTTPS

pulumi config set aitutor-aws:domain-name tutor.education.gov.xx
pulumi config set aitutor-aws:hosted-zone-id Z0123456789ABCDEFGHIJ
pulumi up

O Pulumi pede o certificado, escreve o registo de validação, espera pela emissão, acrescenta o listener HTTPS e redirecciona a porta 80. Conte com uma espera durante a validação; se exceder o tempo, nada mudou e o site continua a ser servido na porta 80.

DEIXE A FERRAMENTA SER DONA DO REGISTO DE VALIDAÇÃO

O certificado é revalidado na renovação usando esse registo DNS. Um registo acrescentado à mão que alguém mais tarde arrume quebra a renovação cerca de onze meses depois — muito depois de alguém conseguir associar os dois acontecimentos.

Passo 4 — Construir e instalar a imagem da aplicação

aws ecr get-login-password | docker login --username AWS \
  --password-stdin <acct>.dkr.ecr.<region>.amazonaws.com
docker build --platform linux/amd64 -t <ecr-url>:v1 .   # amd64 importa em Apple Silicon
docker push <ecr-url>:v1
pulumi config set aitutor-aws:image-tag v1 && pulumi up

./ops/migrate_and_seed.sh                               # tarefa única

Ou envie para o ramo main da sua bifurcação e deixe o fluxo de instalação executá-lo. Aqui as migrações têm de ser uma tarefa única, e não parte do arranque do contentor: o serviço lança todas as tarefas ao mesmo tempo, pelo que migrações no comando de arranque competiriam entre réplicas.

Passos 5 e 6 — Firewall e depois verificação

A firewall começa em modo de contagem, para que possa ver o que bloquearia antes de bloquear seja o que for. Active-a e depois verifique como faria em qualquer caminho:

pulumi config set aitutor-aws:waf-block-mode true && pulumi up

curl -s https://tutor.education.gov.xx/health/     # {"status": "ok", ...}

Depois abra o site, crie uma conta de pessoal, carregue currículo e faça um turno de tutoria.

Os dois formatos offline

FormatoO que éO que precisa
Aplicação offline para computadorLinux, Windows e macOS. Executa um modelo na máquina da sala de aula e nunca comunica para fora. O trabalho sincroniza com um servidor quando existe um acessível; os portáteis provisionados são semeados a partir de um pacote de conteúdos em suporte amovível.Uma máquina de sala de aula capaz de executar um modelo local pequeno. Sem Internet.
Quiosque offlineUma pequena placa que emite a sua própria rede WiFi e serve o tutor num endereço fixo a qualquer navegador da sala. Sem monitor, sem teclado. A primeira resposta após um arranque a frio demora cerca de noventa segundos enquanto o modelo carrega; os turnos seguintes estabilizam nos vinte.Equipamento de classe Jetson. Ou é ponto de acesso ou está ligado à sua rede WiFi, nunca ambos.

Ambos trocam qualidade de tutoria por independência, e a secção 8 é a forma de descobrir em que medida, sobre o seu próprio conteúdo. No quiosque, confirme que modelo está de facto seleccionado: um modelo na nuvem configurado numa placa offline é a falha que o quebra silenciosamente, e é por isso que o comando de estado a assinala.

Sintomas primeiro, porque é assim que se apresentam.

O que vêCausaSolução

Ou defina HTTPS_EDGE=false e mude para a configuração em HTTP simples — apenas numa rede isolada.

Cópias de segurança e restauro

CaminhoComo
AOs scripts acompanham o ficheiro compose: ./backup.sh → ./backups/aitutor-AAAA-MM-DD-HHMM.tar.gz, e ./restore.sh backups/<ficheiro>.tar.gz para o repor. O arquivo contém a base de dados e a media carregada, tomadas em conjunto.
BA base de dados gerida faz cópias automáticas numa janela de 14 dias; restaure pela consola ou pelo script de restauro incluído. A media fica em armazenamento de objectos e é versionada separadamente.

A base de dados guarda a referência a cada figura e o volume guarda o ficheiro, e é por isso que as duas são tomadas em conjunto: uma base de dados restaurada sobre media mais antiga deixa lições com imagens partidas e não comunica qualquer erro.

TRÊS REGRAS QUE SE APLICAM A TODOS OS CAMINHOS

Uma cópia de segurança que só existe na máquina que copia não é uma cópia de segurança. As cópias contêm registos de alunos — guarde-as encriptadas, com acesso restrito às mesmas pessoas que podem chegar ao servidor. E teste um restauro: uma cópia por testar é um palpite, por isso faça-o uma vez numa máquina sobresselente antes de precisar dela.
