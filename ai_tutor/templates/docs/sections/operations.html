AreaWhat to do
BackupDatabase and uploaded media, on a schedule, restored into a scratch instance at least once before students arrive. A backup that has never been restored is not a backup. Scripts ship with the deployment files.
UpgradesPull the new image, run migrations, restart. Migrations are one logical change per file; a backfill against production data is dry-run against a copy first.
SecretsProvider keys, the signing key and the database password live in the platform's secret storage, never in the image or the repository.
MonitoringWatch four things: application health, database health, model provider error rates (the cascade hides a failing provider until it hides two), and daily model spend against the Phase 3 model.
Flagged sessionsA named person reads them weekly during a pilot. This is a safeguarding control, not an analytics dashboard.
Stuck contentLessons left in a generating state after a failed run need a manual reset. Put it in the runbook.
Login lockoutRepeated failures lock the specific account-and-address pair for an hour — not the username alone, which would let anyone lock out a named student, and not the address alone, which would lock out a whole school behind one connection.
