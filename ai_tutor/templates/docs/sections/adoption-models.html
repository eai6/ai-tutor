The offline options in more detail

  • Offline desktop application — Linux, Windows and macOS. Runs a language model on the classroom machine and never calls out. Work syncs back to a server when one is reachable, and provisioned laptops are seeded from a content pack carried on a USB stick.
  • Offline kiosk — a small NVIDIA Jetson board that broadcasts its own WiFi network and serves the tutor to any browser in the room at a fixed address. No monitor, no keyboard, no internet: power it on and students connect. First reply after a cold boot takes about ninety seconds while the model loads; subsequent turns settle to around twenty.

Both trade tutoring quality for independence. A small local model is a weaker tutor than a frontier cloud model, and slower on a machine without a GPU. The platform is built so that this trade-off can be measured rather than argued about — see section 8.

MIGRATION BETWEEN MODELS IS SUPPORTED AND NORMAL

The same application image runs on all of these paths, and content moves between deployments as a curriculum pack. Starting managed to prove the concept and migrating to a country-owned instance later is a supported path, not a rebuild — the platform already runs the same image on two different clouds simultaneously.
