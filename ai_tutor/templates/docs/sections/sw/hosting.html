Njia tatu zinazoungwa mkono za usakinishaji wa seva, pamoja na miundo miwili ya nje ya mtandao. Zote huendesha programu ileile; hutofautiana katika nani anaendesha mashine iliyo chini yake na kiasi gani cha mabomba ya kuzunguka huja nayo. Kinachofuata ni undani wa kiuendeshaji — mwongozo wa kujiendesha mwenyewe huja na programu na hubaki wenye mamlaka kama hivyo viwili vitatofautiana.

Njia A — seva moja

Makontena matatu, mabuku mawili, seva moja. Msingi wa maarifa huhifadhiwa kama vekta ndani ya Postgres, hivyo hakuna hifadhidata tofauti ya vekta ya kuendesha.

        Intaneti
            │
          Caddy            TLS huishia hapa; cheti hupatikana
            │              na kuhuishwa kiotomatiki
            ▼
     Django + Gunicorn  ── buku la maudhui (michoro iliyopakiwa)
            │
            ▼
   PostgreSQL + pgvector ── buku la data

Unachohitaji

  • Seva ya Linux: vCPU 4, GB 8 za RAM, diski GB 60. x86-64 au ARM zote zinafanya kazi. VPS ya GB 2 haitaendesha hii — taswira ni takriban GB 7, ikibeba toleo la CPU la PyTorch, modeli ya utambuzi wa usemi na sauti.
  • Kama unajenga badala ya kuvuta, pangia GB 25 huru: hifadhi ya tabaka ni kubwa kwa raha kuliko matokeo.
  • Docker na programu-jalizi ya Compose.
  • Jina la kikoa linaloelekeza kwenye anwani ya IP ya umma ya seva, huku milango 80 na 443 ikifikika. HTTPS haiwezi kutolewa bila hilo.
  • Angalau ufunguo mmoja wa API wa mtoa modeli — au hakuna, kama unatumia modeli ya ndani iliyofungashwa hapa chini.

Sakinisha

Unahitaji faili tano: fasili ya compose, usanidi wa TLS, kiolezo cha usanidi na hati za nakala rudufu na kurejesha. Zitoe ndani ya taswira iliyochapishwa — hakuna msimbo wa chanzo, hakuna ufikiaji wa hazina, na haziwezi kuwa toleo moja nyuma ya taswira wanayoisanidi.

mkdir -p ai-tutor && cd ai-tutor

docker run --rm ghcr.io/eai6/ai-tutor:latest \
  tar -C /app/deploy/compose -c \
      docker-compose.yml Caddyfile env.example backup.sh restore.sh | tar -x

cp env.example .env
chmod 600 .env

Fungua .env na ujaze kila kitu kilichowekwa alama REQUIRED; kila ingizo linasema ni nini na nini huvunjika bila hilo. Tunga siri hizo mbili badala ya kuzibuni:

python3 -c "import secrets; print(secrets.token_urlsafe(64))"   # SECRET_KEY
python3 -c "import secrets; print(secrets.token_urlsafe(32))"   # POSTGRES_PASSWORD

Kisha vuta taswira na uanze:

docker compose pull        # ~GB 7, mara moja
docker compose up -d
docker compose logs -f app

VUTA KABLA YA KUWASHA

Kama taswira haipo tayari kwenye mashine, docker compose up huijenga kutoka chanzo badala yake — jambo linalohitaji chanzo, takriban GB 25 za diski huru na muda mwingi. Taswira iliyochapishwa ni ya x86-64; kwenye seva ya ARM, nakili hazina na uendeshe docker compose build, ambayo pia ndiyo namna taswira ya ARM inavyotengenezwa. Hakuna kilichofungwa kwenye usanifu mmoja.

Kuanza bila akaunti yoyote ya mtoa huduma

docker compose --profile local-llm up -d

Hiyo huongeza kontena la modeli ya ndani, huvuta modeli ya ~GB 2.6 wakati wa kuanza mara ya kwanza na humwelekeza mkufunzi kwayo kiotomatiki. Ichukulie kama njia ya kuanza bila akaunti ya kibiashara, si kama kitu sawa nayo: modeli ndogo ya ndani ni dhaifu kwa kipimo katika ufundishaji, inahitaji takriban GB 4 za RAM zaidi ya programu, na ni ya polepole kwenye seva isiyo na GPU. Ongeza ufunguo wa mtoa huduma baadaye kisha uanze upya — usanidi wa ndani hujiondoa wenyewe.

Jaribio la kwanza

  1. Unda akaunti ya msimamizi: docker compose exec app python manage.py createsuperuser
  2. Ingia katika https://<kikoa-chako>/admin/ na uweke modeli ipi inatumikia kusudi lipi chini ya LLM → Model configs. Hakuna kinachofanya kazi hadi angalau ufundishaji uelekeze kwa mtoa huduma ambaye umetoa ufunguo wake.
  3. Unda taasisi na upakie mtaala kupitia dashibodi ya mwalimu.
  4. Chukua zamu moja ya ufundishaji. Hilo ndilo jaribio halisi — hutumia hifadhidata, msingi wa maarifa, vitambulisho na maudhui ya picha katika kitendo kimoja. Ukaguzi wa afya haufanyi hivyo.

Kuboresha

cd ai-tutor
docker compose pull
docker compose up -d

Uhamishaji huendeshwa kiotomatiki wakati wa kuanza. Chukua nakala rudufu kwanza. Ili kubandika toleo badala ya kufuata latest, weka IMAGE_TAG=v1.2.0 katika .env — kubandika hufanya uboreshaji kuwa kitu unachochagua, na kurudi nyuma kuwa suala la kubadili mstari mmoja.

Njia B — akaunti yako mwenyewe ya AWS

DNS na ngome mbele, kigawa mzigo kinachomaliza TLS, programu kwenye Fargate katika mitandao midogo binafsi isiyo na anwani ya umma, Postgres inayosimamiwa kando yake, na intaneti ya kutoka tu kupitia lango la NAT. Gharama ya muundo huu iko katika sehemu ya 6.

Unachohitaji kwanza

  • Akaunti ya AWS, na jukumu linaloweza kuunda rasilimali za VPC, ECS, RDS, S3, IAM, WAF na Route 53.
  • Kikoa unachokimiliki — cheti hakiwezi kutolewa kwa jina la seva la kigawa mzigo kinachomilikiwa na AWS.
  • Angalau ufunguo mmoja wa API wa mtoa modeli.
  • Vilivyosakinishwa kwenye kompyuta yako: git, aws CLI v2, pulumi, docker, Python 3.12.
  • Hazina ya msimbo, kwa ajili ya programu ya miundombinu-kama-msimbo iliyo katika infra/aws/. Njia A inaweza kuendeshwa kutoka taswira iliyochapishwa pekee; njia hii haiwezi.

Hatua ya 1 — Nakili na usanidi rundo

git clone <hazina> ai-tutor && cd ai-tutor/infra/aws
python -m venv venv && ./venv/bin/pip install -r requirements.txt

aws configure                 # au aws sso login
pulumi login --local          # hali katika ~/.pulumi; hifadhi nakala rudufu
pulumi stack init prod

pulumi config set aws:region eu-west-1
pulumi config set aitutor-aws:db-instance-class db.t4g.medium
pulumi config set aitutor-aws:db-storage-gb 50
pulumi config set aitutor-aws:min-tasks 1
pulumi config set aitutor-aws:max-tasks 4

# Weka nenosiri la hifadhidata mwenyewe — USIRUHUSU litungwe
pulumi config set --secret aitutor-aws:db-password "<nenosiri refu la nasibu>"
pulumi config set --secret aitutor-aws:django-secret-key "<herufi 50+ za nasibu>"
pulumi config set --secret aitutor-aws:anthropic-api-key "sk-ant-..."

Hatua ya 2 — Washa miundombinu

pulumi up                                        # pitia mpango, kisha thibitisha
pulumi config set aitutor-aws:enable-ecs true    # kisha ongeza huduma
pulumi up

Huduma imezuiliwa nyuma ya bendera hiyo ya pili kwa makusudi, ili msingi uweze kuthibitishwa kabla chochote hakijaendeshwa juu yake.

Hatua ya 3 — Kikoa na HTTPS

pulumi config set aitutor-aws:domain-name tutor.education.gov.xx
pulumi config set aitutor-aws:hosted-zone-id Z0123456789ABCDEFGHIJ
pulumi up

Pulumi huomba cheti, huandika kumbukumbu ya uthibitisho, husubiri kutolewa kwake, huongeza kisikilizi cha HTTPS na huelekeza upya mlango 80. Tarajia isubiri wakati wa uthibitisho; ikiisha muda, hakuna kilichobadilika na tovuti bado inahudumiwa kwenye mlango 80.

ACHA ZANA IMILIKI KUMBUKUMBU YA UTHIBITISHO

Cheti huthibitishwa upya wakati wa kuhuishwa kwa kutumia kumbukumbu hiyo ya DNS. Kumbukumbu iliyoongezwa kwa mkono ambayo mtu baadaye anaisafisha huvunja uhuishaji takriban miezi kumi na moja baadaye — muda mrefu baada ya mtu yeyote kuunganisha matukio hayo mawili.

Hatua ya 4 — Jenga na usakinishe taswira ya programu

aws ecr get-login-password | docker login --username AWS \
  --password-stdin <acct>.dkr.ecr.<region>.amazonaws.com
docker build --platform linux/amd64 -t <ecr-url>:v1 .   # amd64 ni muhimu kwenye Apple Silicon
docker push <ecr-url>:v1
pulumi config set aitutor-aws:image-tag v1 && pulumi up

./ops/migrate_and_seed.sh                               # kazi ya mara moja

Au sukuma kwenye tawi kuu la nakala yako na uache mtiririko wa usakinishaji uifanye. Uhamishaji lazima uwe kazi ya mara moja hapa, si sehemu ya kuanza kwa kontena: huduma huzindua kila kazi kwa wakati mmoja, hivyo uhamishaji ndani ya amri ya kuanza ungeshindana kati ya nakala.

Hatua za 5 na 6 — Ngome, kisha thibitisha

Ngome huanza katika hali ya kuhesabu ili uweze kuona ingezuia nini kabla haijazuia chochote halisi. Iwashe, kisha thibitisha kama ungefanya kwenye njia yoyote:

pulumi config set aitutor-aws:waf-block-mode true && pulumi up

curl -s https://tutor.education.gov.xx/health/     # {"status": "ok", ...}

Kisha pakia tovuti, unda akaunti ya mfanyakazi, pakia mtaala, na uchukue zamu moja ya ufundishaji.

Nakala rudufu na kurejesha

NjiaNamna
AHati huja kando ya faili ya compose: ./backup.sh → ./backups/aitutor-YYYY-MM-DD-HHMM.tar.gz, na ./restore.sh backups/<faili>.tar.gz kuirudisha. Kumbukumbu hushikilia hifadhidata na maudhui ya picha yaliyopakiwa, vikichukuliwa pamoja.
BHifadhidata inayosimamiwa huchukua nakala rudufu za kiotomatiki kwa dirisha la siku 14; rejesha kupitia kiolesura au hati ya kurejesha iliyoletwa. Maudhui ya picha hukaa katika hifadhi ya vitu na yana matoleo kando.

Hifadhidata hushikilia rejeo la kila mchoro na buku hushikilia faili, ndiyo maana hivi viwili huchukuliwa pamoja: hifadhidata iliyorejeshwa dhidi ya maudhui ya picha ya zamani huacha masomo yakiwa na picha zilizovunjika na hairipoti hitilafu yoyote.

KANUNI TATU ZINAZOTUMIKA KWENYE KILA NJIA

Nakala rudufu iliyopo kwenye mashine inayoihifadhi pekee si nakala rudufu. Nakala rudufu zina kumbukumbu za wanafunzi — zihifadhi zikiwa zimefichwa, huku ufikiaji ukiwekewa mipaka kwa watu walewale wanaoweza kufika kwenye seva. Na jaribu kurejesha: nakala rudufu isiyojaribiwa ni kubahatisha, hivyo ifanye mara moja kwenye mashine ya akiba kabla hujaihitaji.
