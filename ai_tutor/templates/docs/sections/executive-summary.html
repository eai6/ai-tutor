The AI Tutor gives a secondary-school student a one-to-one conversational tutor that follows their national syllabus, and gives their teacher a dashboard showing who is stuck and on what. It is a Django web platform: a student works through a lesson in chat, the tutor asks and marks and adapts, and an exit ticket at the end records whether the lesson was learned.

The central claim of this document is that adopting it in a new country is a configuration-and-content exercise, not a rewrite. The platform was built multi-tenant and multi-locale from the beginning: content, users and configuration are scoped to an institution, and the tutor's language, register, examples, grade names, school list and competency thresholds are all data or small pluggable code entries rather than assumptions baked into the engine. Adding a country to the tutor engine is one locale profile entry plus one language rule; no database schema changes.

What is genuinely hard is not the software. It is three things: getting the national syllabus in and reviewed by subject experts, deciding where the language model runs, and teacher adoption. This document is organised around those.

The five things a country adapts

LayerWhat changes
1. Language and registerTutor and interface language, how students are addressed, orthography, technical vocabulary
2. CurriculumNational syllabus → courses, units, lessons, steps, figures, exit tickets, skill graph
3. Local contextPlaces, currency, ecology and the settings of the worked examples a tutor explains through
4. National structuresGrade names, school register, competency bands, terminology, branding, teacher permissions
5. Infrastructure and data residencyWhere it runs, where student data lives, whether model calls leave the country

The one decision that changes everything else

Student conversations are answered by a large language model. In the default configuration that model is operated by Anthropic, OpenAI or Google, which means the student's message leaves the country. No setting changes this, because it is what makes the tutor work. A country can instead run an open model on its own hardware, or use the offline build that runs entirely on a classroom machine — at a measurable cost in tutoring quality that should be measured on that country's own content before a cohort is committed. Decide this first. It determines the deployment model, the cost profile, the data protection assessment and the quality bar for everything that follows.
