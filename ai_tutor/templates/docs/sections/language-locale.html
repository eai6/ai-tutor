Locale codes

Hyphenated lowercase, following the framework's own language-code convention — a language subtag, a hyphen, then a country subtag. The tested deployment uses en-us. The code is the join key across every layer below, so pick it once and do not change it.

The five places a locale is registered

#Registration pointWhat it controls
1The platform language listWhich locales appear in every picker — school default, student preference, course language. A locale absent here cannot be selected.
2The tutor identity profileThe audience clause in the tutor's role: who it believes it is teaching — "Seychelles secondary-school students, grades S3–S5" in the tested deployment. One entry per country; no database change.
3The runtime language ruleThe language and register block injected into the live tutoring prompt on every turn.
4The content-generation language ruleThe same register decisions applied when lessons, teaching scripts and assessment questions are generated.
5The interface translation catalogueStandard translation files for the student and teacher interfaces, including the JavaScript strings.

TWO FAILURE MODES TO KNOW ABOUT

An unregistered locale does not error. The tutor falls back to a generic language instruction and to the default country identity — so a misconfigured course produces content that is roughly the right language and entirely the wrong country. Register all five points, and confirm with a real session before generating a subject. Separately: the runtime language rule sits inside the cached prefix of the tutoring prompt. Once a locale is live, keep its strings byte-stable — an incidental edit invalidates that country's prompt cache and raises its per-turn cost until the cache refills.

Which language wins, per request

Resolution runs in this order, first match wins:

  • The course being taught — inside a tutoring session the lesson's language always wins, regardless of student or school preference. A geography course authored in one language renders in that language for everyone taking it.
  • An explicit language toggle — the visitor's own choice, which is also how an unsigned-in visitor reads the landing page in their language.
  • The student's preference, if they have set one.
  • The school's default language.
  • The platform default.

Register decisions to settle with a native-speaking educator

  • Form of address for the age group — formal or informal.
  • Orthographic standard, where the language has more than one.
  • Which technical vocabulary stays in the standard form of the language.
  • Whether product and brand names are translated (they should not be).
  • Which places, currency, geography and ecology localised examples should draw on — and where localisation should not be forced, because the topic is abstract.
  • An explicit prohibition on switching to another language mid-content, including for headings, affirmations and error messages.

These are written once as a language rule and then apply consistently to generated content and to live tutoring, which is what keeps the two from drifting apart.
